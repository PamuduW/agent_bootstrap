# Lessons

Postmortems and patterns worth remembering. Lighter than ADRs — captures *what happened*, not formal architecture choices.

## Filename

```
YYYY-MM-DD-short-topic.md
```

## Template

```markdown
# Lesson: Title

**Date:** YYYY-MM-DD
**Tags:** #tag1 #tag2

## What happened
Brief narrative.

## Root cause
Why it happened.

## Fix / pattern
What to do next time.

## Links
- Related ADR or project note (optional)
```

## Rules

- Write after incidents, surprises, or repeated friction — not for every task
- Agents may draft; you approve and commit
- Prefer actionable patterns over blame
